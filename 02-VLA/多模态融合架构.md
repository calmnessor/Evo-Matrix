# 多模态融合架构

> VLA 的核心工程问题——视觉 token 和语言 token 如何融合？729 个视觉 token 和几十个文本 token 怎样高效互动？

## 为什么融合难？

多模态融合面临三个核心矛盾：

1. **数量不对称**：视觉 token (SigLIP: 729) vs 文本 token (~20-50 个) — token 数差一个数量级
2. **信息密度不对等**：视觉 token 是空间分布的低级特征，文本 token 是语义密集的高级特征
3. **对齐困难**：视觉的"红色方块"和文本的"red block"需要在同一空间中表示相同概念

## 四种融合范式

### 1. Early Fusion (输入层拼接)

```
视觉 token [N_v, d_m]  +  文本 token [N_t, d_m]
              ↓                    ↓
         拼接 → [N_v + N_t, d_m] → Transformer → 输出
```

**代表**: RT-2, OpenVLA, LLaVA

**实现**：
```python
# OpenVLA 的做法
visual_embeds = projector(vision_output)   # [B, 729, 4096]
text_embeds = llama_embed_tokens(text_ids) # [B, L, 4096]
inputs = torch.cat([visual_embeds, text_embeds], dim=1)
outputs = llama_model(inputs_embeds=inputs)
```

**优点**：
- 实现极简：拼接 + feed forward，让 Transformer 自己学怎么融合
- Self-Attention 天然让每个 token 能看到所有其他 token → 充分交互

**缺点**：
- 视觉 token 数量碾压文本 → 注意力的"焦点"被稀释
- Transformer 的 $O((N_v+N_t)^2)$ 注意力开销 → 视觉 token 多时很贵
- 没有模态特定的计算（全塞一个 transformer）

**适用**: 视觉 token 数量可控（<1000）时是最简单的选择。

### 2. Middle Fusion (中间层注入)

```
图像 → ViT (前半段) → 中间特征 ─┐
                                ├→ Cross-Attention/FiLM → 融合后继续计算
文本 → LLM (前半段) → 中间特征 ─┘
```

**代表**: Flamingo, BLIP-2 (Q-Former), LLaVA-1.5 (部分)

```python
# Flamingo 风格: 在 LLM 层间插入 Cross-Attention gate
class GatedCrossAttentionBlock(nn.Module):
    def __init__(self, d_model):
        super().__init__()
        self.cross_attn = nn.MultiheadAttention(d_model, num_heads=8)
        self.gate = nn.Parameter(torch.zeros(1))  # 可学习的 tanh gate
    
    def forward(self, x, visual_features):
        # x: LLM hidden states [L, B, d]
        # visual_features: [N_v, B, d] (固定，来自 Visual Encoder)
        attn_out, _ = self.cross_attn(
            query=x, key=visual_features, value=visual_features
        )
        return x + torch.tanh(self.gate) * attn_out  # tanh gate 控制注入量
```

**优点**：
- 灵活控制融合的位置和强度
- Cross-Attention 的 Q/K/V 分离 → 计算量 $O(N_t \cdot N_v)$ 而非 $O((N_t+N_v)^2)$
- tanh gate 从 0 开始 → 逐步学会注入视觉信息

**缺点**：
- 架构复杂，需要为融合专门设计模块
- 视觉 token 还是很多 → Cross-Attention 计算量仍不小

### 3. Late Fusion (输出层拼接)

```
图像 → ViT → 视觉特征 [1, d_v] ─┐
                                ├→ 拼接 → MLP → 动作
文本 → LLM → 语言特征 [1, d_l] ─┘
```

**优点**：各自独立编码，模态间互不干扰，计算高效

**缺点**：模态间交互不足，只靠最后的 MLP 无法建立复杂的跨模态关系

**适用**：简单任务或轻量模型

### 4. Q-Former Style (可学习 Query 压缩)

```
视觉特征 [N_v, d_v] (可变长度)
        ↓
  Learned Queries [K, d_q] (固定数量, K << N_v)
        ↓ Cross-Attention (Q=learned, K/V=visual)
  压缩后视觉 token [K, d_q]
        ↓
  送入 LLM (K 通常 32-64)
```

**代表**: BLIP-2, InstructBLIP, Qwen-VL

```python
class QFormer(nn.Module):
    def __init__(self, n_queries=32, d_model=768):
        super().__init__()
        self.query_tokens = nn.Parameter(torch.randn(1, n_queries, d_model))
        
        # Cross-Attention: queries attend to (可变的) visual tokens
        self.cross_attn = nn.MultiheadAttention(d_model, num_heads=8)
        
        # Self-Attention: queries 之间互相交流
        self.self_attn = nn.MultiheadAttention(d_model, num_heads=8)
    
    def forward(self, visual_features):
        B, N_v, D = visual_features.shape
        queries = self.query_tokens.expand(B, -1, -1)  # [B, K, D]
        
        # Queries 之间先交流
        queries = self.self_attn(queries, queries, queries)[0]
        
        # Queries attend 到视觉特征 (从 N_v 提取信息到 K 个 query)
        queries = self.cross_attn(
            query=queries,         # [K, B, D]
            key=visual_features,   # [N_v, B, D]
            value=visual_features  # [N_v, B, D]
        )[0]
        
        return queries  # [B, K, D] — 压缩后的视觉 token
```

**优点**：
- 视觉 token 数固定且少（32-64）→ 大幅减少后续 LLM 的计算量
- Queries 是可学习的"信息提取器"——学会从视觉中提取 LLM 最需要的特征

**缺点**：
- 压缩有信息损失（空间细节可能丢失，对精细操作不利）
- Q-Former 本身需要预训练

## 关键融合机制对比

### Cross-Attention

```python
# 核心: Q 和 K/V 来自不同模态
Q = W_Q @ modality_A   # "A 向 B 提问"
K = W_K @ modality_B   # "B 提供索引"
V = W_V @ modality_B   # "B 提供内容"

output = softmax(Q @ K.T / sqrt(d)) @ V
# 每个 A 的 token 从 B 的所有 token 中提取相关信息
```

**VLA 中的使用**：ACT 的 Decoder 用 Cross-Attention 看 Encoder 的观测特征。

### FiLM (Feature-wise Linear Modulation)

```python
# 语言调制视觉特征
γ, β = MLP(language_embed)       # γ, β ∈ ℝ^{d_vis}
output = γ * visual_features + β  # 逐通道缩放 + 平移
```

**VLA 中的使用**：RT-1 用 FiLM 注入语言到视觉特征，比拼接更轻量。

**优点**：计算量极小（两个向量 × 视觉通道数），适合实时系统
**缺点**：表达能力有限（只能做通道级缩放，不能改变空间关系）

### AdaLN (Adaptive Layer Normalization)

```python
# 条件信息调制 LayerNorm 的参数
α, β, γ = MLP(condition)  # condition = timestep/语言/观测
# AdaLN 变体:
output = γ * LayerNorm(x, α, β) + shift
```

**VLA 中的使用**：扩散策略的 DiT 架构中，用 AdaLN 注入时间步条件和观测条件。

### Gated Injection

```python
# 可学习的门控控制信息注入量
gate = nn.Parameter(torch.zeros(1))
output = x + torch.tanh(gate) * cross_attn(x, visual)
```

**VLA 中的使用**：Flamingo 的 Cross-Attention gate，让模型从"忽略视觉"逐步学会"使用视觉"。

## VLA 模型融合方式总览

| 模型 | 融合方式 | 视觉→LLM 路径 | 特点 |
|------|---------|-------------|------|
| **RT-1** | FiLM (Early) | 用语言调制视觉 | 轻量，语言注入视觉而非反向 |
| **RT-2** | Early Fusion (拼接) | ViT token + text token 拼接 → decoder | 最简单，Self-Attn 全局交互 |
| **OpenVLA** | Early Fusion (拼接) | SigLIP token + text embedding 拼接 → LLaMA | 同上，LoRA 微调融合层 |
| **Flamingo** | Middle Fusion (Cross-Attn Gate) | 在 LLM 层间插入 Cross-Attn | 灵活，gate 控制注入量 |
| **BLIP-2** | Q-Former (压缩) | Learned Queries 压缩视觉 → 送入 LLM | 减少 token 数 |
| **ACT** | Cross-Attention | Decoder Cross-Attn 到 Encoder | 仅视觉 (语言可选) |
| **Diffusion Policy** | FiLM / Cross-Attn | 条件注入去噪网络 | 观测调制噪声预测 |
| **RDT** | AdaLN (DiT 风格) | 条件调制 DiT Block 的 LN | 扩散+语言+观测联合条件 |

## 设计考量

### Token 压缩策略

当视觉 token 太多（>500），考虑压缩：

| 方法 | 压缩比 | 适用 |
|------|--------|------|
| **Q-Former** | N_v → 32-64 | LLM 输入前 |
| **TokenLearner** (RT-1) | 486 → 8 | 空间 token |
| **Perceiver Resampler** | N_v → K (任意) | 通用 |
| **MLP 投影 + 下采样** | 729 → 256 | 简单粗暴 |

### 推理效率考量

- Cross-Attention 复杂度：$O(N_{text} \cdot N_{vis})$ vs Self-Attention 的 $O((N_{text}+N_{vis})^2)$
- Q-Former 压缩后 → LLM 推理大幅加速（token 数减少 10×）
- 对于 7B+ LLM，Self-Attention 的内存消耗是主要瓶颈
