## 一句话总结

π*₀.₆ 通过 **RECAP**（Advantage-Conditioned RL）让 VLA 在真实世界中通过强化学习**持续改进自身策略**，在咖啡制作、叠衣、纸盒组装三个任务上实现了工业级鲁棒性——连续运行 13 小时不失败。

## 核心动机

### 行为克隆的天花板

所有之前的 π 系列模型（以及 RT-1/RT-2/OpenVLA）本质上都在做行为克隆——模仿人类遥操作的演示数据。这有三个根本局限：

```
1. 只能模仿，无法超越
   BC 策略的上限 = 人类专家的水平
   人类专家的成功率 ≈ 70-85%（人也会失误）
   → BC 策略最好也只能到 ~70%

2. 对失败的恢复能力差
   训练数据:  人类从来不会犯错 → 没有"从错误中恢复"的数据
   实际运行:  策略犯了错 → 进入了训练中从未见过的状态
             → 不知道怎么办 → 越做越错 → 崩溃

3. 无法从自身经验中学习
   每次失败都是一条"负样本"数据
   BC 只会拟合正样本 → 负样本被丢弃
   → 策略不会"吃一堑长一智"
```

### 为什么不用 PPO？

PPO 是 RL 的标准方法。但 PPO 需要：
- 显式的 reward 函数（难设计，需要人工标注或复杂检测）
- 策略梯度（高方差，需要大量样本）
- On-policy 数据收集（每次 update 都需新鲜数据）

对于 VLA 这种大模型 + Flow Matching 架构，PPO 的梯度信号太稀疏、方差太大。

RECAP 的洞察：**把 RL 问题"假装"成监督学习问题**。

## 方法：RECAP

### 核心思想：Advantage Conditioning

```
传统 RL (PPO):
  收集 rollout → 算 advantage → 策略梯度 → 更新策略
  ↑ 梯度复杂，方差大

RECAP:
  收集 rollout → 算 advantage → 转为 token → 条件化策略
  "Advantage: positive" → 这个动作好，以后多做
  "Advantage: negative" → 这个动作差，以后少做
  ↑ 本质就是监督学习 —— 适合 Flow Matching VLA!
```

### 三阶段训练

```
阶段 1: 离线 RL 预训练 (Offline RL Pre-training)
┌────────────────────────────────────────────┐
│  在大规模多机器人、多任务演示数据上训练:    │
│                                            │
│  a) VLA 策略 π_θ(a|o, adv_token)          │
│     - 输入观测 o + advantage token         │
│     - 输出动作 a                            │
│     - 用 Flow Matching loss                │
│                                            │
│  b) 价值函数 V_φ(o)                        │
│     - 670M VLM backbone (Gemma 3 初始化)    │
│     - 预测: 距离任务成功还有多少步?         │
│     - 输出: 负步数 (越大越好)               │
│     - Loss: MSE(V_pred, -steps_to_success) │
│                                            │
│  关键: 包含失败数据!                        │
│  - 成功轨迹: steps_to_success → V 逐步增大  │
│  - 失败轨迹: 最后几步 V 骤降                │
│  → V 函数学会了"什么是差的状态"             │
└────────────────────────────────────────────┘
                    ↓
阶段 2: 任务微调 (Fine-tuning)
┌────────────────────────────────────────────┐
│  在目标任务的少量演示数据上微调:            │
│  - 策略: BC on 成功轨迹                     │
│  - 价值函数: V fine-tune                    │
│  → 初始化一个"还不错"的策略                 │
└────────────────────────────────────────────┘
                    ↓
阶段 3: 在线自进化 (Online Self-Improvement)
┌────────────────────────────────────────────┐
│  循环:                                     │
│  1. 策略 π 在真实世界自主执行任务           │
│  2. 收集 (o, a, success/fail) 结果         │
│  3. 可选: 人类遥操作纠正失败点              │
│  4. 更新价值函数 V_φ (用新数据)             │
│  5. 计算 advantage: A(o,a) = r + γV(o') - V(o)
│  6. 更新策略 π_θ:                           │
│     - 正 advantage 的 (o,a) → adv_token="positive"
│     - 负 advantage 的 (o,a) → adv_token="negative"
│     - 用 Flow Matching loss 训练            │
│  7. 回到步骤 1 (用新策略)                   │
└────────────────────────────────────────────┘
```

### Advantage 的计算与编码

```python
# 伪代码：RECAP 的 advantage 计算和条件化

# 价值函数 V_φ 预测"距离成功还有多少步"的负数
# V_φ(o) ∈ [-MAX_STEPS, 0]，越接近 0 = 越接近成功

def compute_advantage(o_t, o_next, success, V):
    # 实际 outcome
    if success:
        r_t = 1.0  # 最终步 = 成功
    else:
        r_t = 0.0  # 失败

    # TD 误差作为 advantage
    advantage = r_t + gamma * V(o_next) - V(o_t)
    return advantage  # >0 = 好于预期, <0 = 差于预期

# 将 advantage 转为条件 token
def advantage_to_token(advantage):
    if advantage > 0:
        return "<|Advantage: positive|>"  # 这个动作值得重复
    else:
        return "<|Advantage: negative|>"  # 这个动作需要改进

# 训练时
for (o, a, advantage) in replay_buffer:
    adv_token = advantage_to_token(advantage)
    # 将 adv_token 拼到 prompt 里
    prompt = f"[{adv_token}] {language_instruction}"
    # Flow Matching loss
    loss = flow_matching_loss(policy(o, prompt), a)
    loss.backward()
```

### 为什么 Advantage Conditioning 比 PPO 更适配 VLA？

| | PPO | RECAP |
|---|-----|-------|
| **梯度类型** | 策略梯度 (高方差) | 监督学习梯度 (低方差) |
| **更新方式** | 梯度上升 (沿 advantage 方向) | Loss 最小化 (正样本权重加大) |
| **与 BC 兼容** | 需要 offline RL 初始化 | 就是 BC + advantage 条件 |
| **样本效率** | 低 (需要大量在线数据) | 高 (可复用离线数据) |
| **架构侵入性** | 需要修改 loss 函数 | 只需加一个 token |
| **对 Flow Matching** | 不支持 | 原生支持 |

## 架构升级：π₀.₆

相比 π₀.₅，π₀.₆ 做了架构升级：

| 组件 | π₀.₅ | π₀.₆ | 变化 |
|------|-------|-------|------|
| VLM Backbone | Gemma 2.6B | **Gemma 3 4B** | 更大更强的 VLM |
| Action Expert | ~300M | **~860M** | 更大的动作专家 |
| 价值函数 | 无 | **670M VLM** | 全新组件 |
| 训练方式 | BC only | **BC → RECAP RL** | 新增 RL |
| 推理 | — | **RTC 推理时执行** | 实时性 |

## 关键结果

### 三项真实世界挑战任务

| 任务 | BC 基线 | BC + Fine-tune | π*₀.₆ (RECAP) | 提升 |
|------|---------|---------------|---------------|------|
| **浓缩咖啡制作** | ~50% | ~65% | **>90%** (13h 连续) | ~2× 成功率 |
| **叠衣服** (11 种衣物) | ~40% | ~55% | **>85%** (2h+ 连续) | ~2× 成功率 |
| **纸盒组装** (工厂) | ~35% | ~55% | **>85%** | ~2.4× 成功率 |

### "自进化"的实际表现

```
实验: 在咖啡制作任务上连续运行

BC only:
  成功率: ~65%
  平均故障间隔: ~3 次尝试
  
  失败模式:
  - 托盘没放到位
  - 咖啡粉洒出
  - 杯子没对准出水口

RECAP 自进化 (5 轮迭代后):
  成功率: >90%
  最长连续运行: 13 小时
  
  改进:
  - 托盘对不准 → 学会了"推一推"确认到位
  - 粉洒了 → 学会了调整倒粉角度
  - 杯子对不准 → 学会了先"轻碰"确认位置再放

  这些"改进"不是人类编程的 → 是 RL 自己探索出来的
```

### 吞吐量翻倍

RECAP 不仅提升成功率，还提升任务吞吐量：

- 策略学会了**更自信的动作**（不需要反复确认）
- RL 信号鼓励"快速且正确"的动作
- 任务完成时间缩短 ~30%

## 贡献与影响

1. **VLA 的 RL 时刻**：首次证明 VLA 可以通过 RL 在真实世界中持续改进
2. **RECAP 方法论**：Advantage Conditioning 让 RL 像监督学习一样简单——只需加一个 token
3. **超越 BC 天花板**：RECAP 训练的策略显著超过了人类专家（BC 只能逼近，RECAP 可以超越）
4. **工业级鲁棒性**：13 小时连续运行 → 逼近工业自动化可靠性
5. **失败即燃料**：失败不再是浪费的实验，而是下一轮 RL 的训练数据——越跑越聪明

## 局限

- RECAP 需要一个可用的 reward 信号（稀疏 reward 如 "成功/失败" 即可，但需要可靠检测）
- 在线 RL 阶段需要真实机器人运行——时间和硬件成本高
- 价值函数的训练质量直接影响 RECAP——差的价值函数 → 差的 advantage → 坏策略
- 尚未证明在多任务、跨具身场景下的 RL 效果
- 安全性：自主运行数小时需要安全监控机制
