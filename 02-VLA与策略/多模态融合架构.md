# 多模态融合架构

> VLA 的核心工程问题——视觉 token 和语言 token 如何融合？

## 三种融合范式

### Early Fusion (输入层融合)
```
[图像 patch] + [文本 token] → 直接拼接 → Transformer
```
- **代表**: RT-2 式架构
- **优点**: 简单，让 Transformer 自己学怎么融合
- **缺点**: 不同模态的 token 数可能严重不平衡

### Middle Fusion (中间层融合)
```
图像 → ViT → 中间特征 ─┐
                        ├→ Cross-Attention → 融合 → ...
文本 → LLM → 中间特征 ─┘
```
- **代表**: Q-Former (BLIP-2), Flamingo
- **优点**: 灵活控制融合深度
- **缺点**: 架构复杂

### Late Fusion (输出层融合)
```
图像 → ViT → 最后特征 ─┐
                        ├→ 拼接 → MLP → 动作
文本 → LLM → 最后特征 ─┘
```
- **优点**: 各自独立编码
- **缺点**: 模态间交互不足

## 关键机制

### Cross-Attention
```python
# 图像特征 attend 语言特征
Q = W_Q @ image_feat  # 查询来自图像
K = W_K @ text_feat   # 键来自文本
V = W_V @ text_feat   # 值来自文本

output = softmax(Q @ K.T / sqrt(d)) @ V
# 每个图像 token 从文本中提取相关信息
```

### FiLM (Feature-wise Linear Modulation)
```python
γ, β = MLP(language_embed)
output = γ * image_features + β  # 逐通道的缩放+平移
```
- RT-1 中使用
- 比拼接更轻量

### AdaLN (Adaptive Layer Normalization)
```python
α, β, γ = MLP(condition)
output = γ * LayerNorm(x, α, β) + shift
```
- Diffusion Transformer 中常用
- 扩散策略中也用

### Q-Former
```
Learned Queries (固定数量)
    ↓ Cross-Attention
Vision Features (可变数量 patch)
    ↓
输出固定数量的 visual token → 送入 LLM
```
- BLIP-2 / InstructBLIP 的核心
- 把视觉信息"压缩翻译"成 LLM 能理解的格式

## VLA 模型中的融合方式

| 模型 | 融合方式 | 细节 |
|------|---------|------|
| RT-1 | FiLM | 语言控制视觉特征的缩放 |
| RT-2 | Early Fusion | 视觉 token + 文本 token 拼接 |
| OpenVLA | Early Fusion | SigLIP token + text token 拼接 → LLM |
| ACT | 不融合 | 只用视觉，语言可选 |
| Diffusion Policy | FiLM / Cross-Attn | 取决于 CNN 还是 Transformer 版本 |

## 设计考量

1. **Token 数量不对称**: 视觉 token (729+) vs 文本 token (几十个)
2. **推理效率**: Cross-Attention 有额外计算
3. **训练稳定性**: 不同模态的梯度和分布需要平衡
4. **可扩展性**: 能否加更多模态（触觉、音频、深度图）？
