# 常见问题排查

> 真机部署的"血泪经验手册"——记录课题组踩过的坑和解决方法。也欢迎补充你自己遇到的坑。

## 症状 → 原因 → 解决方法

### 1. 机器人不动 / 发指令没反应

```
症状: 发了动作命令，机器人不动或动得很奇怪

排查:
  □ 机器人上电了吗? (控制器灯亮 = 上电)
  □ 急停按钮复位了吗? (旋转急停按钮 = 复位)
  □ 机器人模式对吗? (Franka: 蓝色灯 = 自动模式, 白色 = 手动)
  □ 通信通了没? (ping 机器人 IP)
  □ 是否有报错? (Franka: Desk 界面看错误信息)
  □ 动作值是不是太小? (打印验证: print(action))

Franka 特有:
  - 第一次用需要先在 Desk 上 "Unlock" → "Activate FCI"
  - 如果之前急停过, 需要 Releases Brakes
```

### 2. 机器人抖动 / 震动

```
症状: 机器人运行时关节不断颤抖, 发出嗡嗡声

原因 A: 控制增益太高
  解决: 降低阻抗控制刚度
  stiffness=[600,600,600,60,60,60] → 降为 [300,300,300,30,30,30]

原因 B: 动作输出不连续 (VLA 常见!)
  解决: 加 EMA 平滑滤波 (见[[安全机制与防护#动作平滑滤波]])
  smooth(action, alpha=0.3)

原因 C: 传感器噪声 → 被放大
  解决: 检查力传感器是否有偏置 (Desk 界面可重置)

原因 D: 接近奇异点
  解决: 奇异点检测 → 如果接近, 重新规划
  manipulability = sqrt(det(J·Jᵀ))
  if manipulability < 0.01: → 处于/接近奇异点
```

### 3. 抓取总是偏 / 抓不准

```
症状: 相机看到物体在 (x, y, z), 机器人过去抓, 总是偏

原因 A: 手眼标定不准 (最常见!)
  验证: 放一个已知位置的物体 → 相机算位置 → 机器人去碰
  如果误差 > 2cm → 重新手眼标定

原因 B: 相机内参标定漂移
  验证: 重投影误差是否 < 0.5px
  如果 > 1px → 重新相机标定

原因 C: 机器人正运动学不准 (较少见)
  验证: 关节角 → 算末端位姿 → 实测 (用激光笔/尺子)
  如果误差 > 1cm → 需要机器人运动学标定 (专业厂商)

原因 D: 深度相机的系统误差
  RealSense 深度在 >2m 误差变大到 cm 级
  解决: 保持操作距离 0.5-2m

原因 E: 物体被移动了 (相机拍了最开始的, 机器人去抓时已经动了)
  解决: 高频重观测 (不依赖一次静态检测)
```

### 4. VLA 推理太慢 / 控制频率低

```
症状: 控制频率 < 10Hz, 机器人动作一顿一顿

原因 A: 模型太大, GPU 不够
  测量:
    import time; t0 = time.time()
    model(image, text); torch.cuda.synchronize()
    print(f"Infer: {(time.time()-t0)*1000:.1f} ms")
  解决: TensorRT / FP16 / 量化 (见[[模型推理与实时优化]])

原因 B: 图像分辨率太高
  640×480 → 降为 320×240 → 视觉编码快 ~4×

原因 C: 动作块太长 (H=50 → H=25)
  减少每次推理的步数

原因 D: 后台在跑别的东西 (占 GPU)
  检查: nvidia-smi → 看谁在用 GPU
  解决: 关闭无关进程

原因 E: Python GIL 阻塞 (使用异步架构时)
  解决: 推理用独立进程 (torch.multiprocessing)
```

### 5. 动作不连贯 / 中间停顿

```
症状: 机器人做几步 → 停一下 → 再做几步

原因 A: Action chunking 的自然现象
  chunk 内的动作平滑, chunk 间有停顿 (推理那 200ms)
  解决: RTC 异步推理 (见[[模型推理与实时优化#7-实时推理的异步架构]])

原因 B: 通信延迟
  检查: ros2 topic hz /vla/action
  如果频率不稳定 → 检查网络/ROS 2 QoS 设置

原因 C: 安全机制拦截 (动作被 clamp)
  检查 safety_monitor 日志 → 看是否在频繁拦截
```

### 6. 策略在仿真很好，上真机完全不行

```
症状: 仿真 > 90% 成功率, 真机 < 30%

排查顺序:
  1. 看图像: 真机的图像仿真比较 → 差异大吗?
     - 差异大 → 视觉 Sim2Real Gap → 加 DR 训练

  2. 测动作: 同一观测下，仿真输出 A 和真机输出 A' 一样吗?
     - 一样但真机还是不行 → 动力学 Sim2Real Gap
     - 不一样 → 观测 Gap (回到 1)

  3. 查标定: 手眼标定重做 + 验证

  4. 简化任务: 先用硬编码+机视觉做一个最简单版
     (如: "检测红色方块 → 去固定位置 (0.5, 0.0, 0.2)")
     → 如果这都不行 → 标定/控制有问题

  5. 如果简化版可以 → 逐步加复杂度
```

### 7. 夹爪打不开/关不上

```
症状: 夹爪明明发了关指令, 实际没反应

原因:
  - Robotiq: 需要先 activate → 听到 "咔" 一声才就绪
  - Franka Hand: 手指有东西卡住 → 力保护自动回弹
  - 气压夹爪: 没接气源
  - USB 通信掉线 (检查 dmesg)

解决:
  Robotiq: gripper.activate()  (每次上电后必须)
  Franka: 检查有无异物, 用 gripper.move(width, speed=0.02) 低速试
```

### 8. 相机帧率不对 / 掉帧

```
症状: 30fps 的相机实际只到 15fps

原因:
  - USB 带宽不够 (多相机共用同一 USB Hub)
  - 分辨率太高 → 数据量大
  - ROS 2 QoS 设置不对 (丢帧策略)
  - 光线太暗 → 曝光时间长

解决:
  - 每个相机接独立 USB 3.0 端口 (不要用 Hub!)
  - 降低分辨率: 640×480 @ 30fps (不是 90fps)
  - 检查: ros2 topic hz /wrist/rgb → 看频率
```

### 9. TF 树报错 / 坐标系对不上

```
症状: RViz 中机器人模型散架, TF 变换链断裂

原因:
  - 有人改了 URDF 但没更新 TF publisher
  - frame_id 名字拼错了 (如 "base_link" vs "base_footprint")
  - 时间戳不同步

解决:
  # 查看 TF 树
  ros2 run tf2_tools view_frames.py
  # 生成 frames.pdf → 看断裂位置

  # 检查具体变换
  ros2 run tf2_ros tf2_echo base_link wrist_camera
```

### 10. "it worked yesterday"

```
症状: 昨天还能跑, 今天同样的代码跑不通了

可能原因:
  □ 谁动了标定文件? (检查 git diff)
  □ 谁重启了机器人/相机? (IP 变了? 配置丢了?)
  □ 系统更新了? (pip install 升级了某个包?)
  □ 场景变了? (光照不同? 物体换了位置?)
  □ 硬件松动? (相机/夹爪的螺丝松了?)

解决:
  - 用 git bisect 定位代码变更
  - 先跑最简单 test (joint move), 确认底层正常
  - 检查 conda/pip 环境是否有变化
```

## 调试实战技巧

### 最小可工作系统 (MWE)

```python
"""
每次遇到问题, 先退回到最小可工作系统:

MWE = 相机 + 机器人, 无 VLA, 硬编码动作

如果 MWE 能跑:
  → 问题在 VLA 推理或策略
  → 逐步加回模块: + 视觉编码 → + LLM → + 动作生成

如果 MWE 不能跑:
  → 问题在基础硬件/通信/标定
  → 不必查 VLA, 先修底层
"""

def mwe_test(robot, camera):
    """最小可工作系统测试"""
    # 1. 相机会有画面
    img = camera.capture()
    assert img is not None and img.shape == (480, 640, 3), "相机异常"

    # 2. 机器人能动
    initial_joints = robot.get_joint_positions()
    target_joints = initial_joints + 0.1
    robot.move_joints(target_joints)
    time.sleep(0.5)
    actual_joints = robot.get_joint_positions()
    assert np.allclose(actual_joints, target_joints, atol=0.05), "机器人未移动"

    # 3. 夹爪能动
    robot.gripper.open()
    time.sleep(0.5)
    robot.gripper.close()
    time.sleep(0.5)

    print("✅ MWE 通过: 硬件正常")
    return True
```

### 日志定位

```python
# 在关键位置加时间戳日志
import logging
logging.basicConfig(level=logging.DEBUG)

def vla_predict_with_logging(model, obs):
    t0 = time.time()
    logging.debug(f"[VLA] 相机采集: {(t0 - obs.capture_t)*1000:.1f}ms")
    
    vision_feat = model.vision_encoder(obs.image)
    t1 = time.time()
    logging.debug(f"[VLA] 视觉编码: {(t1-t0)*1000:.1f}ms")
    
    action = model.action_head(vision_feat)
    t2 = time.time()
    logging.debug(f"[VLA] 动作生成: {(t2-t1)*1000:.1f}ms")
    logging.debug(f"[VLA] 总计: {(t2-t0)*1000:.1f}ms")
    
    return action
```

### 对比测试

```python
# A/B 测试: 改了一个东西 → 和 baseline 对比
def ab_test(baseline_config, new_config, robot, num_episodes=20):
    """A/B 对比两个配置"""
    results = {"baseline": [], "new": []}

    for ep in range(num_episodes):
        # Baseline
        robot.reset()
        success = run_episode(robot, baseline_config)
        results["baseline"].append(success)

        # New
        robot.reset()
        success = run_episode(robot, new_config)
        results["new"].append(success)

    baseline_rate = sum(results["baseline"]) / len(results["baseline"])
    new_rate = sum(results["new"]) / len(results["new"])

    print(f"Baseline: {baseline_rate:.2%}")
    print(f"New:      {new_rate:.2%}")
    print(f"Diff:     {new_rate - baseline_rate:+.2%}")

    return results
```
