# 大语言模型与微调

> VLA 的 L = Language——理解指令，推理任务，甚至生成动作。

## 为什么具身智能需要大语言模型？

机器人传统上靠规则和有限状态机执行任务："检测到杯子 → 执行抓取 → 移动到位 → 释放"。这能处理 **50 个预定义任务**，但面对自然语言指令就崩溃了。

大语言模型 (LLM) 给机器人带来了三样关键能力：

| 能力 | 例子 | 传统方法 |
|------|------|----------|
| **语义理解** | "帮我把桌上那个红色的杯子拿过来" → 识别目标物体、颜色、位置 | 写死关键词匹配 |
| **任务规划** | "先打开冰箱，找到牛奶，倒入杯中" → 拆分为 4 个子任务序列 | 人工编写 FSM |
| **常识推理** | "杯子快掉下桌沿了，你先推回去再抓" | 无法处理 |

**一句话**：LLM 从互联网文本学到了"物理世界的常识"，VLA 把这份常识映射为机器人的动作。

## 1. 核心概念

### 1.1 自回归语言模型

**原理**：给定序列 $x_1, x_2, ..., x_{t-1}$，预测第 $t$ 个 token $x_t$：

$$P(x_{1:T}) = \prod_{t=1}^{T} P(x_t \mid x_{<t})$$

- 训练时：喂入 "$x_1, ..., x_{t-1}$"，让模型预测 $x_t$，跟正确 token 算 Cross-Entropy Loss
- 推理时：一个 token 一个 token 地生成
- GPT 系列、LLaMA 系列、Qwen 系列都属此类

**关键直觉**：模型每生成一个 token，都要依赖之前所有已生成的内容。这意味着——
- 前文矛盾 → 后文会混乱
- 给好的提示 (prompt) → 生成更好的回答
- 这也是 VLA 中需要把视觉信息"注入"进 LLM 的原因：视觉是重要的"前文"

### 1.2 Tokenizer：把文字变成数字

**BPE (Byte-Pair Encoding)** 是目前主流方案：

```
原始文本: "机器人抓取杯子"
BPE 分词: ["机器", "人", "抓取", "杯子"]  → token IDs: [15234, 118, 45672, 8901]
```

**两个重要概念**：
- **词表大小 (Vocabulary Size)**：LLaMA-7B 约 32000。越大 → 同意思能用更少 token 表达
- **OOV 问题**：BPE 通过子词切分解决——未见过"抓取杯"也能拆成"抓取"+"杯"

**VLA 中的特殊处理**：
- RT-2 把动作空间的离散化动作也变成 token（"动作 token"），让 LLM 自回归生成"文本 → 动作"序列
- OpenVLA 将 256 个离散化的动作 bin 映射为 256 个特殊 token，直接扩充词表

### 1.3 Scaling Law

**核心公式** (Kaplan et al., 2020; Chinchilla 修正)：

$$L \propto C^{-0.154} \cdot N^{-0.074} \cdot D^{-0.095}$$

**VLA 中的启示**：
- 更大的 LLM backbone → 更好的语言理解 → 可能更好的机器人推理
- 但是：**机器人数据极稀缺**（不像互联网文本几乎无限），纯 LLM scaling 对 VLA 不直接适用
- 这是为什么 VLA 用"大 LLM + 少量机器人数据 LoRA 微调"的原因

**Chinchilla 最优** (DeepMind, 2022)：对给定计算预算，模型大小和训练 token 数应同比增加（1:20 比例）。但 LLM 已开始超越 Chinchilla——用更多数据训练"小"模型来降低推理成本（如 LLaMA-3-8B 训练了 15T tokens）。

## 2. Transformer 快速回顾

> 详见 [[../Transformer与注意力/Transformer与注意力|Transformer与注意力]]，这里只列 VLA/微调相关的关键点。

```
LLM (Decoder-only Transformer):

Token Embedding
    ↓
[Transformer Block] × N 层
    ├── Multi-Head Self-Attention (Causal Mask: 只能看到上文)
    ├── Add & Norm
    ├── Feed-Forward Network (FFN)
    └── Add & Norm
    ↓
LM Head → 预测下一个 token
```

**三个与微调直接相关的组件**：
- **Attention 的 Q/K/V 投影矩阵**：$W_Q, W_K, W_V$ → LoRA 通常加在这些上
- **FFN 的权重**：$W_{\text{up}}, W_{\text{down}}$ → 存储了大部分"知识"
- **Causal Mask**：保证生成时 $x_t$ 只能 attend 到 $x_{1}, ..., x_{t-1}$

### 2.1 主流 LLM 架构对比

| 模型 | 参数量 | 训练数据 | 特点 | VLA 中使用 |
|------|--------|----------|------|-----------|
| **LLaMA-3** | 8B/70B | 15T tokens | 开源最强之一 | OpenVLA 用 LLaMA-7B |
| **Qwen2.5** | 7B/72B | ~18T tokens | 中文支持好 | 国产 VLA 常用 |
| **GPT-4o** | 未公开 | 未公开 | 闭源最智能 | 云端 VLA 方案 |
| **Gemma** | 2B/7B/27B | ~6T tokens | 轻量友好 | 轻量 VLA 方案 |
| **DeepSeek-V3** | 671B (MoE) | 14.8T tokens | MoE 高效 | 云端复杂任务推理 |

## 3. LLM 在 VLA 中的实际角色

### 3.1 三种使用范式

```
范式 1: LLM 作为任务规划器 (SayCan, Code-as-Policies)
  自然语言指令 → LLM 拆解为子任务 → 底层控制器执行每个子任务
  特点: LLM 不直接控制动作，只负责"想"

范式 2: LLM 作为 VLA Backbone (RT-2, OpenVLA)
  图像+指令 → LLM 处理 → 直接输出动作 token
  特点: LLM 端到端参与感知→决策→控制

范式 3: LLM 作为世界模型 (3D-VLA, UniSim)
  LLM 预测"如果我执行这个动作，场景会变成什么样"
  特点: LLM 负责"想象"
```

### 3.2 关键模型架构

```
RT-2 (Google DeepMind, 2023):
  图像 → ViT → 视觉 token ─┐
  指令 → Tokenizer → 文本 token ─┤→ PaLI-X / PaLM-E Backbone
                                                    ↓
                            解码器自回归生成: [动作 token 1] [动作 token 2] ...

OpenVLA (Stanford et al., 2024):
  图像 → SigLIP/DINOv2 → 视觉 token ─┐
  指令 → LLaMA Tokenizer → 文本 token ─┤→ LLaMA-7B (LoRA 微调)
                                                    ↓
                            离散动作 bin → 末端位姿 (Δx, Δy, Δz, Δr, Δp, Δy)

π₀ (Physical Intelligence, 2024):
  多模态输入 → 自研 VLM → Flow Matching 去噪 → 连续动作序列
  特色: 不靠离散化，直接输出连续动作
```

### 3.3 为什么 LLM Backbone 有用？（争议与讨论）

**支持方**：
- LLM 预训练时学到大量"物理常识"（重力、遮挡、容器关系）
- 语言理解 → 将模糊指令转为精确动作
- 数据复用：互联网文本 ∞，机器人数据寥寥无几

**反对方**：
- LLM 对物理交互的理解是文本层面的，不是传感器层面的
- LLM 的因果注意力适合文本，但机器人推理是否需要更灵活的结构？
- 推理延迟：7B+ 模型推理 100ms+，实时控制困难

> **课题组视角**：短期内 LLM Backbone 仍是主流（效果确实好），但轻量化（1B-3B 参数量）是趋势。

## 4. 新手学习路线

### 第一阶段：理解概念（1-2 天）
1. 用 ChatGPT / 本地 LLM 聊天，建立对"自回归生成"的直觉
2. 阅读 [The Illustrated Transformer](https://jalammar.github.io/illustrated-transformer/)
3. 搞清楚：tokenizer 如何工作？

### 第二阶段：动手微调（3-5 天）
1. 用 HuggingFace PEFT 库跑通 QLoRA 微调 LLaMA-3.2-3B
2. 自己准备一个小数据集（50-100 条），微调看看效果
3. 尝试换 rank / alpha / target_modules

### 第三阶段：VLA 关联（3-5 天）
1. 读 RT-2 论文：理解"动作 token"如何融入 LLM 词表
2. 读 OpenVLA 论文/博客：理解 LoRA 在 VLA 中的作用
3. 如果资源允许：跑通 OpenVLA 的 LoRA 微调脚本
