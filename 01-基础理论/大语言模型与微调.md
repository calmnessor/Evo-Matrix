# 大语言模型与微调

> VLA 的 L = Language——理解指令，推理任务，甚至生成动作。

## 为什么具身智能需要大语言模型？

机器人传统上靠规则和有限状态机执行任务："检测到杯子 → 执行抓取 → 移动到位 → 释放"。这能处理 **50 个预定义任务**，但面对自然语言指令就崩溃了。

大语言模型 (LLM) 给机器人带来了三样关键能力：

| 能力 | 例子 | 传统方法 |
|------|------|----------|
| **语义理解** | "帮我把桌上那个红色的杯子拿过来" → 识别目标物体、颜色、位置 | 写死关键词匹配 |
| **任务规划** | "先打开冰箱，找到牛奶，倒入杯中" → 拆分为 4 个子任务序列 | 人工编写 FSM |
| **常识推理** | "杯子快掉下桌沿了，你先推回去再抓" | 无法处理 |

**一句话**：LLM 从互联网文本学到了"物理世界的常识"，VLA 把这份常识映射为机器人的动作。

## 1. 核心概念

### 1.1 自回归语言模型

**原理**：给定序列 $x_1, x_2, ..., x_{t-1}$，预测第 $t$ 个 token $x_t$：

$$P(x_{1:T}) = \prod_{t=1}^{T} P(x_t \mid x_{<t})$$

- 训练时：喂入 "$x_1, ..., x_{t-1}$"，让模型预测 $x_t$，跟正确 token 算 Cross-Entropy Loss
- 推理时：一个 token 一个 token 地生成，每次生成的结果作为下一步的输入
- GPT 系列、LLaMA 系列、Qwen 系列都属此类

**关键直觉**：模型每生成一个 token，都要依赖之前所有已生成的内容。这意味着——
- 前文矛盾 → 后文会混乱
- 给好的提示 (prompt) → 生成更好的回答
- 这也是 VLA 中需要把视觉信息"注入"进 LLM 的原因：视觉是重要的"前文"

### 1.2 Tokenizer：把文字变成数字

LLM 不理解文字，只理解数字。Tokenizer 就是把文字转为数字序列的"翻译官"。

**BPE (Byte-Pair Encoding)** 是目前主流方案：

```
原始文本: "机器人抓取杯子"
BPE 分词: ["机器", "人", "抓取", "杯子"]  → token IDs: [15234, 118, 45672, 8901]
```

**两个重要概念**：
- **词表大小 (Vocabulary Size)**：LLaMA-7B 约 32000，GPT-4 更大。越大 → 同意思能用更少 token 表达
- **OOV (Out-Of-Vocabulary) 问题**：BPE 通过子词切分解决——未见过"抓取杯"也能拆成"抓取"+"杯"

**VLA 中的特殊处理**：
- RT-2 把动作空间的离散化动作也变成 token（"动作 token"），让 LLM 自回归生成"文本 → 动作"序列
- OpenVLA 将 256 个离散化的动作 bin 映射为 256 个特殊 token，直接扩充词表

### 1.3 Scaling Law：做大做强的数学基础

**核心公式** (Kaplan et al., 2020; 后续有 Chinchilla 修正)：

$$L \propto C^{-0.154} \cdot N^{-0.074} \cdot D^{-0.095}$$

其中 $L$ = 损失, $C$ = 计算量, $N$ = 参数量, $D$ = 数据量。

**VLA 中的启示**：
- 更大的 LLM backbone → 更好的语言理解 → 可能更好的机器人推理
- 但是：**机器人数据极稀缺**（不像互联网文本几乎无限），纯 LLM scaling 对 VLA 不直接适用
- 这是为什么 VLA 用"大 LLM + 少量机器人数据 LoRA 微调"的原因

**Chinchilla 最优** (DeepMind, 2022)：对给定计算预算，模型大小和训练 token 数应该同比增加（1:20 的比例）。但 LLM 已开始超越 Chinchilla——用更多数据训练"小"模型来降低推理成本（如 LLaMA-3-8B 训练了 15T tokens）。

## 2. Transformer 快速回顾

> 详见 [[Transformer与注意力]]，这里只列 VLA/微调相关的关键点。

```
LLM (Decoder-only Transformer):

Token Embedding
    ↓
[Transformer Block] × N 层
    ├── Multi-Head Self-Attention (Causal Mask: 只能看到上文)
    ├── Add & Norm
    ├── Feed-Forward Network (FFN)
    └── Add & Norm
    ↓
LM Head → 预测下一个 token
```

**三个与微调直接相关的组件**：
- **Attention 的 Q/K/V 投影矩阵**：$W_Q, W_K, W_V$ → LoRA 通常加在这些上
- **FFN 的权重**：$W_{\text{up}}, W_{\text{down}}$ → 存储了大部分"知识"
- **Causal Mask**：保证生成时 $x_t$ 只能 attend 到 $x_{1}, ..., x_{t-1}$

### 2.1 主流 LLM 架构对比

| 模型 | 参数量 | 训练数据 | 特点 | VLA 中使用 |
|------|--------|----------|------|-----------|
| **LLaMA-3** | 8B/70B | 15T tokens | 开源最强之一 | OpenVLA 用 LLaMA-7B |
| **Qwen2.5** | 7B/72B | ~18T tokens | 中文支持好 | 国产 VLA 常用 |
| **GPT-4o** | 未公开 | 未公开 | 闭源最智能 | 云端 VLA 方案 |
| **Gemma** | 2B/7B/27B | ~6T tokens | 轻量友好 | 轻量 VLA 方案 |
| **DeepSeek-V3** | 671B (MoE) | 14.8T tokens | MoE 高效 | 云端复杂任务推理 |

## 3. 微调方法详解

### 3.1 为什么需要微调？

预训练的 LLM 见过互联网上几乎所有文本，但它：
- 没见过你实验室的操作规程
- 不知道"抓取杯柄而非杯身"这种物理约束
- 无法把语言输出映射为 6-DoF 动作

**微调 = 在预训练的基础上，用少量领域数据让模型适应新任务。**

### 3.2 Full Fine-Tuning（全量微调）

**做法**：所有参数参与反向传播。

| 优点 | 缺点 |
|------|------|
| 最大程度的领域适应 | 显存需求极大 (7B 全量 ≈ 56GB+) |
| 不受低秩假设限制 | 灾难性遗忘风险 |
| 对极端分布偏移效果最好 | 保存 N 份全量模型 = N×14GB 磁盘 |

**适用场景**：有大量高质量领域数据（几十万条以上），不差算力。

### 3.3 LoRA (Low-Rank Adaptation) — VLA 微调标配

**核心假设**：微调时权重的更新量 $\Delta W$ 具有低秩结构——即不需要改动所有参数方向，改动少数几个"方向"就能适应新任务。

**做法**：冻结原权重 $W$，在旁边加可训练的低秩矩阵 $BA$：

$$W' = W + \Delta W = W + B \cdot A$$

其中 $W \in \mathbb{R}^{d \times k}$，$B \in \mathbb{R}^{d \times r}$，$A \in \mathbb{R}^{r \times k}$，且 $r \ll \min(d, k)$（典型 $r=8$ 或 $r=16$）。

```
原始前向: h = W @ x
LoRA 前向: h = W @ x + B @ A @ x
              ^^^^^^^^   ^^^^^^^^^^^
               冻结        可训练 (只有 B 和 A)
```

**参数量对比** (LLaMA-7B, $r=8$)：
- 全量微调：7B 参数
- LoRA：约 4M 参数（仅加在 Q, V 投影上）→ 不到全量的 **0.06%**

**LoRA 的超参数**：
- **rank $r$**：一般 8/16/32。rank 越高 → 表达能力越强 → 显存越大
- **$\alpha$**：缩放因子，实际学习率 = $\alpha / r$。常用 $\alpha=16$ with $r=8$
- **target_modules**：加在哪些层上。常见: `["q_proj", "v_proj"]` 或 `["q_proj", "k_proj", "v_proj", "o_proj"]`

**为什么 VLA 用 LoRA**：
- OpenVLA (LLaMA-7B) 只需每新任务 ~10MB 的 LoRA 权重
- 一个基础模型 + 20 个 LoRA = 20 种技能
- 切换任务 = 切换 LoRA 权重（毫秒级）

### 3.4 QLoRA — 消费级 GPU 也能微调大模型

**在 LoRA 基础上加三招**：
1. **NF4 量化**：把 16-bit 权重压到 4-bit（0.5 字节/参数）
2. **双重量化**：连量化常数的存储也优化
3. **分页优化器**：显存不够时自动把梯度换到 CPU

**效果**：原来 48GB 显存才能跑 Llama-7B 全量微调，QLoRA 只需 **8-10GB**——一张 RTX 3060 就够。

**代价**：训练速度比 LoRA 慢 ~30%，收敛可能略差。

### 3.5 其他微调方法

| 方法 | 原理 | 参数量 | 适用场景 |
|------|------|--------|----------|
| **Adapter** | 在 Transformer Block 间插入小 MLP | 中等 (~2-5%) | 多任务切换 |
| **Prefix Tuning** | 在输入前拼接可学习的虚拟 token | 极少 | 纯语言任务 |
| **Prompt Tuning** | 仅学习输入 embedding 层的软 prompt | 最少 | 轻量任务适配 |
| **IA³** | 学习三个缩放向量 $(l_k, l_v, l_{ff})$ | 极少 | 极低资源 |
| **DoRA** | LoRA + 方向/幅度分解 | 略多于 LoRA | 学习能力更强 |

> **课题组建议**：先掌握 LoRA（最常用），再了解 QLoRA（显存不够时）。其他方法作为知识储备即可。

### 3.6 选型速查

| 场景 | 推荐方法 | 典型显存 (7B) |
|------|---------|-------------|
| 有 A100/4090，数据量大 | Full Fine-Tuning | 56+ GB |
| 有中等 GPU，追求效果 | LoRA (r=16, α=32) | 18-24 GB |
| 消费级 GPU (3060/4070) | QLoRA (r=8) | 8-12 GB |
| 云端 API (GPT-4o) | Prompt 工程 + Few-shot | 0 (按 token 付费) |

## 4. LLM 在 VLA 中的实际角色

### 4.1 三种使用范式

```
范式 1: LLM 作为任务规划器 (SayCan, Code-as-Policies)
  自然语言指令 → LLM 拆解为子任务 → 底层控制器执行每个子任务
  特点: LLM 不直接控制动作，只负责"想"

范式 2: LLM 作为 VLA Backbone (RT-2, OpenVLA)
  图像+指令 → LLM 处理 → 直接输出动作 token
  特点: LLM 端到端参与感知→决策→控制

范式 3: LLM 作为世界模型 (3D-VLA, UniSim)
  LLM 预测"如果我执行这个动作，场景会变成什么样"
  特点: LLM 负责"想象"
```

### 4.2 关键模型架构

```
RT-2 (Google DeepMind, 2023):
  图像 → ViT → 视觉 token ─┐
  指令 → Tokenizer → 文本 token ─┤→ PaLI-X / PaLM-E Backbone
                                                    ↓
                            解码器自回归生成: [动作 token 1] [动作 token 2] ...

OpenVLA (Stanford et al., 2024):
  图像 → SigLIP/DINOv2 → 视觉 token ─┐
  指令 → LLaMA Tokenizer → 文本 token ─┤→ LLaMA-7B (LoRA 微调)
                                                    ↓
                            离散动作 bin → 末端位姿 (Δx, Δy, Δz, Δr, Δp, Δy)

π₀ (Physical Intelligence, 2024):
  多模态输入 → 自研 VLM → Flow Matching 去噪 → 连续动作序列
  特色: 不靠离散化，直接输出连续动作
```

### 4.3 为什么 LLM Backbone 有用？（争议与讨论）

**支持方**：
- LLM 预训练时学到大量"物理常识"（重力、遮挡、容器关系）
- 语言理解 → 将模糊指令（"小心一点拿"）转为精确动作
- 数据复用：互联网文本 ∞，机器人数据寥寥无几

**反对方**：
- LLM 对物理交互的理解是文本层面的，不是传感器层面的（"知道"推会动 vs "感受过"推动的力反馈）
- LLM 的因果注意力适合文本，但机器人推理是否需要更灵活的结构？
- 推理延迟：7B+ 模型推理 100ms+，实时控制困难

> **课题组视角**：短期内 LLM Backbone 仍是主流（因为效果确实好），但轻量化（1B-3B 参数量）是趋势。

## 5. 动手实战：用 QLoRA 微调 LLaMA

### 5.1 环境准备

```bash
pip install transformers peft bitsandbytes accelerate datasets
```

### 5.2 最小可运行示例

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from peft import LoraConfig, get_peft_model, TaskType
from datasets import Dataset

# 1. 加载量化模型 (QLoRA)
model_name = "meta-llama/Llama-3.2-3B-Instruct"

model = AutoModelForCausalLM.from_pretrained(
    model_name,
    load_in_4bit=True,               # 4-bit 量化
    bnb_4bit_compute_dtype=torch.bfloat16,
    device_map="auto",               # 自动分配 GPU
)
tokenizer = AutoTokenizer.from_pretrained(model_name)
tokenizer.pad_token = tokenizer.eos_token  # LLaMA 默认无 pad_token

# 2. 配置 LoRA
lora_config = LoraConfig(
    r=8,                              # rank
    lora_alpha=16,                    # 缩放
    target_modules=["q_proj", "v_proj"],  # 通常只加在 Q, V 上
    lora_dropout=0.05,
    bias="none",
    task_type=TaskType.CAUSAL_LM,     # 自回归任务
)

model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# 输出: trainable params: 3,407,872 || all params: 3,216,795,648 || trainable%: 0.1060

# 3. 准备数据 (示例: 指令格式)
data = [
    {"text": "### Instruction: 把红色方块推到蓝色圆圈的右边\n### Response: 末端移动到(0.3, 0.1, 0.05)，夹爪闭合，向右推20cm"},
    # ... 更多数据
]
dataset = Dataset.from_list(data)

def tokenize(examples):
    return tokenizer(examples["text"], truncation=True, max_length=512)

dataset = dataset.map(tokenize)

# 4. 训练
trainer = transformers.Trainer(
    model=model,
    args=TrainingArguments(
        output_dir="./lora-vla",
        per_device_train_batch_size=4,
        gradient_accumulation_steps=4,   # 等效 batch_size=16
        num_train_epochs=3,
        learning_rate=2e-4,              # LoRA 学习率通常比全量高
        fp16=True,
        logging_steps=10,
        save_strategy="epoch",
    ),
    train_dataset=dataset,
)
trainer.train()

# 5. 保存 LoRA 权重 (仅 ~10MB!)
model.save_pretrained("./lora-vla-final")

# 6. 推理时加载
# from peft import PeftModel
# model = PeftModel.from_pretrained(base_model, "./lora-vla-final")
```

### 5.3 微调技巧速查

| 问题 | 解决方案 |
|------|---------|
| 训练不稳定 / loss 震荡 | 降低 lr (1e-4)，增加 warmup_ratio (0.1) |
| 过拟合 / 验证 loss 上升 | 增加 lora_dropout (0.1)，减小 rank |
| 显存不够 | 减小 batch_size，增大 gradient_accumulation，降低 max_length |
| 生成质量差 | 增大 rank (16→32)，添加更多 target_modules (k_proj, o_proj) |
| 灾难性遗忘 | 混合少量通用数据 (replay)，或降低 lr |

### 第一阶段：理解概念（1-2 天）

3. 如果资源允许：跑通 OpenVLA 的 LoRA 微调脚本（官方有 colab）
